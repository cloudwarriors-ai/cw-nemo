# GitHub Issue Management

GitHub Issue Management ensures engineering transparency, delivery accountability, and leadership visibility across all active repositories. QA acts as the steward of issue hygiene, reporting accuracy, and lifecycle consistency.

## Issue Management

**Guide:** [Creating & Managing Issues in GitHub (cloudwarriors-ai)](https://docs.google.com/document/d/1o__QhVgJCe-67nIQ771-zFHGwTsaIRTIiAEHD5PPof0/edit?usp=drive_link)

### Reporting Cadence
* Provide a weekly report on GitHub Issues related to relevant repositories to All CSD Members
* Issues are reported weekly or at two-week intervals, as operationally required

### Required Issue Fields

Ensure issues are marked properly and updated with data relevant to the stage and responsible party:

| Field | Options |
|-------|---------|
| Assignee | Tasked developer |
| Priority Level | High, Medium, Low |
| Skill Level | High, Medium, Low |
| Status | In Progress, In Dev – Awaiting QA, In Dev – QA Approved |
| Type | Tasks, Bug, Feature |

### Developer Updates
* Ensure updates are made by developers to ensure visibility and communication is clear and concise on what is required
